Overview

What is AlphaHound?

AlphaHound is a fully automated trading engine. It ingests 9 real data sources every 15 minutes, detects when different classes of market participants disagree beyond their historical norm, sizes positions using the Kelly Criterion, and executes paper trades on Alpaca without human intervention.

📡
Signal Detection
Measures cross-source divergence using a D-score (standard deviations from 90-day baseline). When institutional flow and retail sentiment disagree — that's the edge.
🧮
Kelly Sizing
Position sizes computed from Half-Kelly criterion. Higher D-values unlock larger allocations. Tiered caps prevent overexposure on any single signal.
⚡
Leveraged Routing
HIGH and EXTREME tier signals route to 3× leveraged ETFs. XLF SHORT becomes FAZ LONG — same exposure, no short-selling mechanics, no PDT issues.
🛡️
Multi-Layer Gates
Every trade passes 3 gates: Technical Gate (MACD/RSI/EMA/Volume/Momentum), Macro Context (global risk-off check), and Portfolio Cap (60% max deployed).
🌍
Global Context
Overnight Asian and European index levels, US futures, VIX, DXY, Gold and Oil fetched every cycle. RISK_OFF globally blocks long entries and reduces position sizes.
📊
Hit Rate Validation
Every signal logged with a resolve_by date. On that date, close price vs entry is compared. Hit rate table auto-populates. Gate: 55%+ before going live.

Core Algorithm

The Divergence Score (D-Value)

The D-value is the engine's heartbeat. It measures how much the data sources disagree with each other, in standard deviations from the 90-day historical baseline for that ticker.

D-Value Formula
D = σ_cross_source / σ_historical_90d
σ_cross_source = std deviation of weighted sentiment means across all sources for this ticker right now
σ_historical_90d = rolling 90-day baseline std dev from divergence_events — what's "normal" disagreement for this ticker
Statistical Gate
p-value < 0.01 (1000-sample permutation null test)
Both D ≥ 2.0 AND p < 0.01 must pass. Eliminates random noise.
D-ValueInterpretationAction
< 2.0Normal background noiseIgnored entirely
2.0 – 4.0Mild divergenceMonitor only — dashboard visible, no execution
4.0 – 8.0High conviction signalExecute STANDARD tier (10% bankroll)
8.0 – 20.0Very strong divergenceExecute via 3× leveraged ETF (20% bankroll)
> 20.0Extreme / exceptionalExecute via 3× leveraged ETF (30% bankroll)

Execution

Position Sizing

Position sizes calculated using Half-Kelly Criterion — mathematically optimal bet-sizing that maximises long-run growth while limiting drawdown risk.

Signal Probability
base_p = min(0.92, 0.50 + (d_value / 20.0))
D=4.0 → p=0.70. D=20.0 → p=0.92 (capped). Alignment bonus: +0–10% if majority of sources agree on direction.
Half-Kelly Position Size
kelly_raw = (p − q) → kelly_half = kelly_raw × 0.5 → position = bankroll × min(kelly_half, tier_cap)
p = signal probability, q = 1 − p. Halving the raw Kelly fraction prevents ruin on losing streaks.
ModifierSourceEffect
Tier capD-value tier10% / 20% / 30% hard cap on position_pct
Tech gate WEAK3/5 indicators pass50% size reduction
Tech gate REJECT≤2/5 indicators passTrade blocked entirely
Macro CAUTIOUSGlobal ETF price changesSize reduced proportionally
Macro RISK_OFFGlobal ETF price changesLONG trades blocked entirely
Portfolio capAlpaca account equityNo new positions if deployed ≥ 60%
Example — XLF D=38.9 EXTREME on $20k bankroll:
base_p=0.92 → kelly_raw=0.84 → kelly_half=0.42 → capped at 30% EXTREME → $6,000 into FAZ.
If tech gate WEAK (3/5): $3,000. If tech gate REJECT: blocked.

Risk Management

Exit Logic

The close_positions step checks all open trade_log entries every 15-minute cycle against three exit triggers.

TriggerConditionAction
Hard exit dateresolve_by date has passed (stored in trade_log)Close at market — no questions asked
Stop lossCurrent price breached stop_price in trade_log notesClose at market immediately
Signal fadeDivergence D < 1.5 (edge resolved itself)Close — reason for trade no longer exists
Stop Loss Calculation
stop_pct = max(5%, min(25%, 100% / (D × 2)))
D=4.0 → stop=12.5%. D=10.0 → stop=5.0%. Higher conviction signals get tighter stops.

Key Monitoring Queries

-- Pipeline health (run in DBeaver)
SELECT step, status, rows_affected, duration_ms, error, started_at
FROM pipeline_runs ORDER BY started_at DESC LIMIT 20;

-- Active signals right now
SELECT e.canonical_symbol, de.d_value, de.p_value, de.time
FROM divergence_events de JOIN entities e ON e.entity_id = de.entity_id
WHERE de.time >= now() - interval '2 hours'
ORDER BY de.d_value DESC;

-- Open paper positions
SELECT e.canonical_symbol, tl.side, tl.size, tl.alpaca_status
FROM trade_log tl JOIN entities e ON e.entity_id = tl.entity_id
WHERE tl.alpaca_order_id IS NOT NULL AND tl.closed_at IS NULL;

-- Hit rate (populates May 14-15)
SELECT window_days, hit_rate_pct, total_signals, computed_at
FROM hit_rate ORDER BY computed_at DESC;
